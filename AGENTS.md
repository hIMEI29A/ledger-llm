## Architecture invariants

- Batch-first end to end: ingress → classifier → batch scheduler → backend adapters → reconciliation. Do not add per-request paths that bypass batching.
- Lock-free hot paths. Channels are stage boundaries; only `sync.Pool`, `sync/atomic`, `sync.Once`, and `sync.WaitGroup` where strictly necessary. No mutexes in ingress, classifier, scheduler, dispatcher, or reconciler. Preserve the single-owner rule per stage in `design.md` D2.
- Classifier: pure Go, p99 ≤ 1 ms for 8 KiB payloads, no network or disk I/O in classification.
- Exactly three tiers: `local`, `mid`, `high`.
- OSS core = router + usage metrics. Billing dashboard, chargeback, and FinOps allocation are gated and live in a separate repository.
- Planned layout: `cmd/ledger-llm`, `internal/{config,ingress,pipeline,classifier,scheduler,adapters,metrics,usage,admin}`, `pkg/adapter`, `api/{proto,gen}`. See `design.md` D1.
